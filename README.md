# Cplusplus-Program

1. Who was the client? What type of software did they want you to design?
The Gaming Room is a video game company that wanted to take their existing game, "Draw It or Lose It," and expand it. Originally, it was only available on one platform, but they wanted a software design that would allow it to be cross-platform, like playing on a web browser. They needed a design that would let multiple players connect, communicate, and play together in real-time across different devices using a client-server model.

2. What did you do particularly well in developing this documentation?
I did a good job of breaking down the project's complex requirements into clear, easy-to-understand sections. I made sure to clearly outline the differences between what happens on the client side (the player's screen) and what happens on the server side (behind the scenes).

3. What about the process of working through a design document did you find helpful when developing the code?
Writing the design document acted like creating a blueprint for a house. It was helpful because it gave me a clear plan to follow. By figuring out the logic and structure ahead of time, I didn't have to guess how different parts of the code should interact with each other while I was actually programming.

4. If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?
If I could revise one part, I would add more detail to the security and data protection sections. I would improve it by being more specific about exactly how user data, passwords, and game states are encrypted and protected as they travel back and forth to the server.

5. How did you interpret the user’s needs and implement them into your software design? Why is it so important to consider the user’s needs when designing?
I focused heavily on making sure the game would run smoothly on multiple platforms and be easy for players to join. It is incredibly important to consider the user's needs early in the design phase because if the software is frustrating to use or doesn't do what the user actually wants, they won't use it—no matter how well the code is written.

6. How did you approach designing software? What techniques or strategies would you use in the future to analyze and design a similar software application?
I approached the design by looking at the big picture first, and then breaking the application down into smaller, manageable pieces (like the game engine, the player teams, and the server connections). In the future, I will definitely continue using UML diagrams and object-oriented design strategies early on to map out how everything connects before I write a single line of code.
